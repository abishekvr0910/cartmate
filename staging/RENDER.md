## Create and inspect

Create a Render Blueprint from `render.yaml` on the private branch. The first deployment must show one `cartmate-staging` web service, a disk mounted at `/var/data`, region `frankfurt`, one instance, and no auto-deploys. The service must start with a clean `/var/data/cartmate.db`; never upload the development database or production data. Render provides HTTPS and a public `onrender.com` URL. The application limits staging OTP to the allowlisted numbers and requires login for people/ping/hotspot discovery, but the homepage and health metadata remain publicly reachable. Do not call this a private, invite-ready environment without an approved access-control and privacy review.

Read-only checks on the HTTPS origin:

Run `python staging/preflight.py --base-url https://YOUR-STAGING-ORIGIN` from an operator machine for the checks below. It never sends SMS; it prints a HOLD if `/api/ready` is blocked. Use `--require-ready` for the final invitation gate.

- `GET /api/health`: 200, environment `staging`, users `0`, OTP set to the chosen carrier provider (`twilio` or `smsapi`), SOS `disabled`.
- `GET /api/ready`: 503 with explicit blockers until the SMS gateway, active pilot-admitted human moderator, persistent database path, and other configured guards are valid; it can then return 200 while `identity_verification_available` remains false. Neither liveness nor readiness is pilot approval.
- Demo tokens return 401. Unauthenticated discovery returns 401. An unlisted phone gets 403 at OTP request/verify/login/register and causes no carrier send.
- Browser loads React, exchanges a fresh bearer session through `POST /api/auth/ws-ticket`, and connects to `wss://<host>/ws?ticket=...`. Raw session tokens in WebSocket URLs are rejected in staging/production. No `VITE_WS_URL` is needed for this same-origin deployment.

After these checks and explicit approval for a single SMS, run `python staging/otp_rehearsal.py --base-url https://YOUR-STAGING-ORIGIN --test-phone +48XXXXXXXXX --yes-send-one-sms` from a trusted operator machine. The script prompts privately for the received code and checks wrong-code denial, replay, authorization, and logout. Confirm gateway outage produces HTTP 503 without claiming delivery. Run Gemini's separate multi-user browser suite only after its staging fixtures are reviewed; never use demo tokens against staging.

## Data and rollback policy

The app writes SQLite and its WAL sidecars under `/var/data`. Render's disk persists across restarts, but a disk-backed service has one instance and incurs brief deploy downtime. Do not place schema changes in Render's pre-deploy command because that command cannot access the attached disk. The image includes `ops/cartmate_backup.py` for an operator-initiated online backup, e.g. `python /app/ops/cartmate_backup.py --db /var/data/cartmate.db --out /var/data/backups --tag predeploy`. This is **not** an offsite backup: securely export and verify a copy outside Render, set retention/encryption/access controls, and rehearse an offline restore before any live cohort. Render's automatic disk snapshots are not a safe substitute for SQLite logical backup/restoration.

Rollback requires a reviewed procedure, a fresh verified online backup, stopping the app before any database restore, and checking WAL/SHM state. Do not restore a Render disk snapshot over SQLite. Keep auto-deploy off until hosted CI, backup/recovery, provider, and security gates have passed.
